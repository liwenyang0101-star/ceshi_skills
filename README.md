# ceshi_skills
是一个面向测试工作者用例编写 Skill。它用于将需求文档、开发设计、页面行为、参数配置、运行结果、API 行为和缺陷描述，整理为结构化、可执行、可导入 Excel 的中文功能测试用例。

## 核心能力

- 从需求材料中抽取角色、范围、规则、状态、异常和验收口径。
- 先生成 `需求梳理`，再设计测试用例，保证需求点和用例模块可追踪。
- 自动识别冲突、歧义、缺失验收标准，并写入 `需求确认点`。
- 按最新版原子性规则编写用例：一条用例只保留一个主操作，前置导航和准备数据放入 `resource`。
- 支持需求优先的技术用例去重：不因开发设计列出接口、表、缓存就机械生成重复用例。
- 可生成固定 Excel 工作簿，包含 `用例`、`需求确认点`、`需求梳理` 三张表。
- 严格处理 `creator`：只有用户明确提供邮箱时才填写，否则全部留空，不推断、不保留超链接。
- 导出前后进行内容、覆盖、格式、字体、边框和空白行校验。

## 适用场景

- 根据 PRD / 需求文档生成测试用例。
- 根据开发设计补充功能验证点和风险点。
- 根据 UI 行为、参数配置、API 行为生成可执行用例。
- 根据缺陷描述生成修复验证和回归测试用例。
- 生成团队统一格式的 Baizhi Excel 测试用例工作簿。

## 输出结构

默认 Excel 输出包含三张工作表：

1. `用例`：结构化功能测试用例。
2. `需求确认点`：记录待产品、开发、测试确认的问题。
3. `需求梳理`：拆解需求内容、业务规则、验收口径、来源、覆盖模块和开发设计/技术影响。

该 Skill 的目标不是输出泛泛的测试建议，而是生成可落地执行、可追踪、可导入、符合团队格式的测试资产。
